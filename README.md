# وب‌سایت شخصی آرش جنت‌آبادی

وب‌سایت نمونه‌کار دوزبانه با Next.js و `next-intl`. نسخه انگلیسی با مسیر `/en` و نسخه فارسی با مسیر `/fa` در دسترس است. جهت نمایش فارسی به‌صورت خودکار راست‌چین و انگلیسی چپ‌چین می‌شود.

## پیش‌نیازها

- Node.js نسخه ۲۰ یا بالاتر (ترجیحاً نسخه LTS)
- npm؛ همراه Node.js نصب می‌شود
- دسترسی اینترنت برای نصب وابستگی‌ها
- Git برای دریافت و به‌روزرسانی کد (اختیاری)
- حساب Resend فقط برای فعال‌کردن ارسال فرم تماس

## راه‌اندازی در محیط توسعه

در ترمینال، به پوشه پروژه بروید و وابستگی‌های ثبت‌شده در `package-lock.json` را نصب کنید:

```bash
cd next-portfolio
npm ci
```

برای تنظیم آدرس سایت و فرم تماس، فایل نمونه را به فایل محلی تبدیل کنید:

```bash
cp .env.example .env.local
```

در Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
```

مقادیر فرم تماس را در `.env.local` تنظیم کنید (جزئیات در بخش [تنظیمات محیطی](#تنظیمات-محیطی)). برای اجرای خود سایت، تنظیم کلید ایمیل الزامی نیست.

```bash
npm run dev
```

سپس این آدرس‌ها را باز کنید:

- انگلیسی: <http://localhost:3000/en>
- فارسی: <http://localhost:3000/fa>

## دستورهای پروژه

| دستور | کاربرد |
|---|---|
| `npm ci` | نصب دقیق وابستگی‌های ثبت‌شده در lockfile |
| `npm run dev` | اجرای سرور توسعه |
| `npm run build` | ساخت نسخه نهایی و بررسی کد و TypeScript توسط Next.js |
| `npm run start` | اجرای نسخه نهایی؛ ابتدا باید `npm run build` اجرا شده باشد |

## ویرایش محتوای سایت

متن‌های قابل‌نمایش در سایت به دو زبان نگهداری می‌شوند. هنگام اضافه‌کردن یا تغییر متن، نسخه انگلیسی و فارسی را با هم به‌روز کنید.

| چه چیزی را می‌خواهید تغییر دهید؟ | فایل یا محل |
|---|---|
| نام، عنوان و معرفی صفحه اصلی، متن‌های درباره من، عنوان بخش‌ها، فرم تماس و SEO | [`messages/en.json`](./messages/en.json) و [`messages/fa.json`](./messages/fa.json) |
| اهداف، توانمندی‌ها و دسته‌بندی‌های مهارت | `goals`, `expertise`, `skills` در [`src/data/data.ts`](./src/data/data.ts) |
| سوابق کاری و تحصیلات | `experience` و `education` در [`src/data/data.ts`](./src/data/data.ts) |
| پروژه‌ها و دسته‌بندی فیلتر پروژه‌ها | `projects` و `categories` در [`src/data/data.ts`](./src/data/data.ts) |
| ایمیل، شبکه‌های اجتماعی، عکس، رزومه و نمایش بخش بازارهای مالی | [`src/config.ts`](./src/config.ts) |
| رنگ‌ها، فونت‌ها، فاصله‌ها و نمایش واکنش‌گرا | [`src/app/globals.css`](./src/app/globals.css) |
| ترتیب بخش‌های صفحه اصلی | [`src/app/[locale]/page.tsx`](<./src/app/[locale]/page.tsx>) |
| ساختار و رفتار یک بخش | فایل متناظر در [`src/components/sections/`](./src/components/sections/) |
| آیکون تگ‌ها و نگاشت آیکون به نام مهارت | [`src/components/ui/Icon.tsx`](./src/components/ui/Icon.tsx) |
| تنظیم زبان‌ها و جهت نمایش | [`src/i18n/`](./src/i18n/) و [`src/app/[locale]/layout.tsx`](<./src/app/[locale]/layout.tsx>) |

### محتوای دوزبانه

در فایل‌های ترجمه، کلیدهای متن باید در هر دو فایل `en.json` و `fa.json` وجود داشته باشند. برای افزودن متن جدید:

1. کلید متن را با ترجمه انگلیسی در `messages/en.json` اضافه کنید.
2. همان کلید را با ترجمه طبیعی فارسی در `messages/fa.json` قرار دهید.
3. در کامپوننت، متن را از سیستم ترجمه (`getTranslations` یا `useTranslations`) بخوانید؛ متن ثابت را مستقیم در کامپوننت ننویسید.
4. JSON باید معتبر بماند؛ بین اعضا ویرگول بگذارید و از ویرگول اضافه بعد از آخرین عضو استفاده نکنید.

زبان‌های فعال فعلی `en` و `fa` هستند. برای اضافه‌کردن زبان جدید، فقط افزودن فایل ترجمه کافی نیست؛ تنظیمات مسیریابی در `src/i18n/routing.ts`، نوع زبان در `src/types/index.ts`، محتوای دوزبانه داده‌ها و جهت نمایش در layout نیز باید به‌روزرسانی شوند.

### مهارت‌ها و تجربه

داده‌های `src/data/data.ts` برای هر متن دوزبانه از دو مقدار `en` و `fa` استفاده می‌کنند. برای نمونه، یک گروه مهارت به این شکل تعریف می‌شود:

```ts
{
  t: { en: "Frontend & Web Development", fa: "فرانت‌اند و توسعه وب" },
  items: [
    { n: { en: "Next.js", fa: "Next.js" } },
    { n: { en: "HTML", fa: "HTML" } },
  ],
}
```

در گروه موبایل، توضیح نیز باید برای هر دو زبان وارد شود. برای سابقه کاری، عنوان (`role`)، مدت (`dur`) و توضیحات (`desc`) را به هر دو زبان تکمیل کنید. تحصیلات با عنوان `field` و نام دانشگاه `institution` نگهداری می‌شود.

### افزودن پروژه

یک دسته با شناسه یکتا در `categories` تعریف کنید و سپس پروژه را در `projects` قرار دهید. مقدار `cat` پروژه باید با شناسه یکی از دسته‌ها برابر باشد. `slug` آدرس صفحه جزئیات پروژه را تعیین می‌کند.

```ts
{
  slug: "sample-project",
  cat: "web",
  name: { en: "Sample Project", fa: "پروژه نمونه" },
  desc: { en: "Project description.", fa: "توضیحات پروژه." },
  tech: ["Next.js", "HTML", "CSS"],
  github: "https://github.com/username/project",
  demo: "https://example.com",
  status: { en: "In progress", fa: "در حال انجام" },
}
```

فیلدهای `tech`, `github`, `demo` و `status` اختیاری هستند. برای لینک‌های ناموجود، فیلدهای لینک را حذف کنید یا خالی بگذارید. پس از افزودن پروژه، صفحه آن با مسیر `/en/projects/sample-project` یا `/fa/projects/sample-project` در دسترس است.

### عکس و فایل رزومه

- عکس را در `public/images/` قرار دهید و مسیر آن را در `CONFIG.photo` در قالبی مانند `/images/profile.png` وارد کنید.
- فایل‌های PDF رزومه را در `public/resumes/` قرار دهید و مسیر انگلیسی و فارسی را جداگانه در `CONFIG.resume.en` و `CONFIG.resume.fa` بنویسید.
- فایل‌های داخل `public/` با همان مسیر نسبی از ریشه سایت در مرورگر در دسترس هستند.

### ظاهر، بخش‌ها و آیکون‌ها

رنگ‌های اصلی در ابتدای `src/app/globals.css` تعریف شده‌اند. تغییرات CSS را در هر دو اندازه دسکتاپ و موبایل بررسی کنید. فونت فارسی و انگلیسی و ویژگی `dir` در `src/app/[locale]/layout.tsx` تنظیم می‌شوند.

برای افزودن آیکون اختصاصی یک تگ، شکل SVG را در مجموعه آیکون‌های `src/components/ui/Icon.tsx` تعریف و سپس نام تگ را در `iconForTag` به آن وصل کنید. نگاشت تگ‌ها در پروژه برای نام‌های فارسی و انگلیسی در نظر گرفته شده است. بخش مستقل امنیت سایبری در سایت وجود ندارد؛ تگ «هک و امنیت» در `expertise` قرار دارد.

ترتیب فعلی بخش‌ها در صفحه اصلی در `src/app/[locale]/page.tsx` مشخص شده است. برای تغییر ظاهر یک بخش، کامپوننت همان بخش را در `src/components/sections/` و استایل‌های مربوط را در `src/app/globals.css` ویرایش کنید.

## تنظیمات محیطی

مقادیر را در `.env.local` (محیط محلی) یا Environment Variables سرویس میزبانی (محیط انتشار) قرار دهید:

| متغیر | کاربرد |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | آدرس اصلی سایت برای metadata و SEO؛ در صورت خالی‌بودن از مقدار پیش‌فرض پروژه استفاده می‌شود |
| `RESEND_API_KEY` | کلید API سرویس Resend برای ارسال ایمیل فرم تماس |
| `CONTACT_TO_EMAIL` | آدرسی که پیام‌های فرم به آن فرستاده می‌شوند |
| `CONTACT_FROM_EMAIL` | فرستنده ایمیل؛ اختیاری، مقدار پیش‌فرض در کد استفاده می‌شود |

فرم تماس فقط وقتی ایمیل ارسال می‌کند که `RESEND_API_KEY` و `CONTACT_TO_EMAIL` تنظیم شده باشند. فرستنده‌ی واردشده در Resend باید برای حساب شما مجاز باشد. در غیر این صورت فرم خطا می‌دهد و موفقیت ساختگی نشان نمی‌دهد.

مقادیر محرمانه را در کد یا Git ثبت نکنید. `.env.local` در `.gitignore` قرار دارد؛ فایل `.env.example` فقط برای معرفی نام متغیرهاست و نباید حاوی کلید واقعی باشد.

## انتشار روی Vercel

1. مخزن را به Vercel متصل کنید؛ تنظیمات پیش‌فرض Next.js مناسب است.
2. در تنظیمات پروژه، متغیرهای محیطی موردنیاز را برای محیط‌های انتشار وارد کنید. برای فرم تماس، متغیرهای Resend را نیز تنظیم کنید.
3. مقدار `NEXT_PUBLIC_SITE_URL` را روی دامنه نهایی سایت بگذارید.
4. هر دو مسیر `/en` و `/fa` را پس از انتشار بررسی کنید.
